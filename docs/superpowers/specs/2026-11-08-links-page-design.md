# Links 友链页设计

## 目标

为博客新增 `/links/` 页面和顶栏入口。页面借鉴参考站的 88×31 友链墙结构，但沿用 Cavill's Blog 现有的配色、留白、边框、字体和响应式导航，不复制参考站的复古视觉皮肤。

## 顶栏

- 不删除、替换或隐藏任何现有入口。
- 桌面端与移动端菜单顺序固定为：Posts、Tags、Links、About、Archives、Search、Theme。
- Links 使用与 Posts、Tags、About 相同的文字链接、悬停效果、焦点样式和波浪线激活态。
- Archives、Search、Theme 的图标、标签和交互保持不变。

## 页面结构

`/links/` 复用现有的 `Layout`、`Header`、`Breadcrumb`、`Main` 和 `Footer`，保持站点级 SEO、主题和响应式行为一致。主体顺序固定为：

1. 页面标题和中文交换友链说明。
2. 申请友链时应提供的完整 88×31 卡片 HTML 示例。
3. `Link to me` 面板：左侧展示自有卡片，右侧只显示复制按钮，不直接展示自有卡片 HTML。
4. `Friend Links` 友链墙；初始数据为空时显示简洁空状态。
5. Giscus 评论区。

介绍文案为：“这里收录互联网的朋友们。只接受 88×31 的卡片形式——我觉得这些卡片是互联网的邮票，而我喜欢集邮。欢迎通过 Email 联系我，或在评论区留言。申请时请提供以下 HTML：”

申请格式使用可直接替换内容的完整 HTML：

```html
<a href="https://example.com/">
  <img
    src="https://example.com/button.gif"
    width="88"
    height="31"
    alt="站点名称"
  />
</a>
```

空状态文案为：“友链墙还是空的，期待第一位互联网邻居。”

## 自有按钮

- 目标地址：`https://blog.cavill.site/`
- 图片地址：`https://picgocloud.com/m/5c51c36c-707a-4905-b006-f9e368afb58c.gif`
- 固定尺寸：88×31
- 替代文本：`Cavill's Blog`
- 面板在桌面端横向排列，在窄屏上允许纵向堆叠。
- 复制按钮提供以下完整 HTML，访客复制后即可直接使用，但页面不直接展示源码：

```html
<a href="https://blog.cavill.site/">
  <img
    src="https://picgocloud.com/m/5c51c36c-707a-4905-b006-f9e368afb58c.gif"
    width="88"
    height="31"
    alt="Cavill's Blog"
  />
</a>
```

- 复制按钮使用浏览器剪贴板 API；成功后显示“已复制”，失败时显示“复制失败”，状态变化通过 `aria-live` 向辅助技术播报。

## 友链数据与渲染

- 新增独立的本地数据模块，定义 `FriendLink` 类型和空的 `friendLinks` 数组。
- 每项包含 `name`、`url` 和 `imageUrl`，以后新增友链只需编辑数据模块。
- 非空时按照 88×31 原始尺寸紧凑换行，保留图片替代文本；页面不裁切、不拉伸按钮。
- 空数组时不渲染占位按钮，只显示带虚线边框的空状态。
- 远程图片加载失败时由浏览器展示 `alt` 文本，不增加运行时重试或占位脚本。

## 国际化与面包屑

- 导航字符串新增 `nav.links = "Links"`。
- 页面字符串新增 Links 标题、描述和空状态，保持现有英文 UI 类型完整；交换说明可以直接使用中文内容。
- 面包屑识别 `links`，显示与顶栏一致的 `Links` 标签。

## 评论

- 将文章页现有的 Giscus 配置抽取为可复用的 `Comments` 组件。
- 文章页与 Links 页均渲染同一个组件，避免仓库、分类、语言和主题配置漂移。
- Links 页评论区位于友链墙之后，继续使用 `pathname` 映射，使 `/links/` 拥有独立讨论串。
